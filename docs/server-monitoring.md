# サーバー監視とDiscord通知

[ドキュメント一覧](README.md) / [運用機能](operations.md)

管理者用の「サーバー」画面で確認します。閲覧専用・公開担当の利用者はアクセスできません。既存のサイト別監視は「運用状況」で引き続き確認できます。

## 有効にする

初めて使うサーバーは [新規導入](install.md)、導入済みサーバーは [更新手順](upgrade.md) を完了してください。`pjas-agentd` と `pjas-monitor.timer` の状態を確認してから、通知先を設定します。

管理画面の「接続設定と初回準備」で通知方法を **Discord** にします。Discordの「サーバー設定 → 連携サービス → ウェブフック」で発行した `https://discord.com/api/webhooks/.../...` を入力して保存し、テスト送信してください。空欄なら保存済みURLを維持します。URLはパスワードと同様の秘密情報です。root専用の管理情報に保存し、画面や通知には再表示しません。

実装時には実際のDiscord URLが提供されていないため、外部への試験通知は送っていません。通知する文章は最大950文字に短縮し、全体・利用者・ロールへのメンションを無効にします。従来の汎用Webhook・メール通知も利用できます。サイト側で通知を有効にしている障害・バックアップ失敗も同じ通知先へ送ります。

## 監視内容

| 項目 | 判定・操作 |
| --- | --- |
| CPU・メモリ | 90%以上が3測定続くと通知。CPUは前回との差で測定するため初回は測定待ち |
| ディスク | `/`、サイト領域、管理情報領域の空き10%未満、または1GB未満 |
| 主要サービス | Apache、導入済みPHP-FPM、pjas-agentd、管理画面、自動監視タイマーの状態 |
| セキュリティ更新 | APTのローカル一覧を1時間ごとに確認。セキュリティ更新候補と再起動要求を表示 |
| 更新一覧の鮮度 | 保存済みRelease情報が2日以上前・未取得なら注意。必要に応じサーバーで `sudo apt update` を実行 |
| SSH認証失敗 | ssh/sshdのjournalに記録された直近10分・最大2000行を集計。20件以上で通知。ユーザー名・IP・本文は監視データに保存しない |
| ctrl認証失敗 | 操作記録のパスワード・二段階認証失敗を直近10分で集計。20件以上で通知。制限前に拒否した要求は含まない |
| 設定変更 | Apacheのサイト設定、systemdのローカルservice/timerとserviceの追加設定、cron.d、crontab、SSH設定のハッシュを比較。追加・変更・削除を記録 |
| バックアップ | 定期バックアップ有効サイトについて、予定間隔＋2時間以内の成功記録を確認 |
| サービス再起動 | Apacheと導入済みPHP-FPMだけ。現在のパスワードと影響確認が必須。設定検査に失敗したら実行しない。要求と成功を操作記録に保存 |

既存の毎分タイマーを使用します。サイト数や処理時間によって間隔が伸びる場合があります。画面からの測定は55秒以内なら保存値を再利用します。CPU・メモリは直近24時間・最大1440点、お知らせは90日、設定変更は最新100件を保存します。画面の推移は各時間帯の最後の測定値です。

異常・復旧への状態変化で通知し、同じ異常を毎分通知しません。送信エラーは5分以上空けて最大5回、発生後24時間以内に再送します。再送時には対象の通知が遅れて届く場合があります。ネットワークの応答が失われた場合の完全な重複排除や配信保証はありません。通知先未設定の場合は再送しません。「確認済み」は人が読んだ記録であり、異常を解消する操作ではありません。

## 仕様上の範囲

- サーバー自身が停止するとDiscordへ通知できません。外部からの死活監視は別途必要です。外部監視先への生存通知は今回実装していません。
- 更新は既存APTキャッシュの確認のみです。ネットワーク経由の一覧更新・更新適用・自動再起動・IP自動遮断は行いません。全依存ソフトウェアのCVE検査ではありません。
- journal以外のSSHログや、別のユニット名・追加認証方式は集計対象外です。ログに記録されない攻撃は検知できません。
- 設定監視は最大1000ファイル・各1MBまでで、リンクは対象外です。初回測定を基準にし、測定間に変更して元に戻したものは検知できません。本文の保存・差分表示や「ctrlによる変更」の自動判定はしません。操作記録と照合してください。署名付きの改ざん防止保管ではなく、rootを奪われた場合の検知を保証しません。
- 同じwww-dataで動くサイト間の分離は別課題です。この監視機能はサイトの実行権限を分離しません。
- 証明書は既存のサイト監視でOrigin証明書を確認します。Cloudflareエッジ証明書の期限監視は今回追加していません。
