# 構成と権限

[ドキュメント一覧](README.md) / [開発・検証](development.md)

現在の実装の入口、プロセス、保存先を説明します。導入コマンドは [新規導入](install.md)、操作手順は [サイト運用](sites.md) にまとめています。

## プロセスと接続

```text
運用者のブラウザー
  │ HTTPS（アクセス元制限）
  ▼
Apache: 管理画面のVirtualHost
  │ HTTP / 127.0.0.1:8184
  ▼
pjas-control-web.service（専用HTTPサービス）
  │ FastCGI / /run/php/pjas-control.sock
  ▼
PHP-FPM: pjas-controlプール（実行ユーザー pjas-control）
  ├── 管理用SQLite DB
  └── Unixソケット /run/pjas-agent.sock
        ▼
      pjas-agentd.service（root）
        ├── 配置・公開先の切替
        ├── Apache設定検査・サービス操作
        └── root管理の台帳・鍵・バックアップ

pjasctl / pjas-tick（pjas-control）
  └── 同じアプリ層・agent RPCを利用
```

ブラウザー向けルートは [public/index.php](../public/index.php) にあります。CLIはPHPのアプリ層とagent RPCを直接利用します。UI・CLI共通の外部REST APIや、APIトークンで認証する公開APIは実装していません。

デプロイ等の長時間処理はagentの子プロセスで実行し、作業状態・ジョブログを管理画面へ返します。ブラウザーはSSEでジョブログを追跡します。すべての操作が同じ非同期ジョブ方式ではなく、v2の設定・初期化等には同期RPCもあります。

## 権限の境界

| 層 | 主な役割と権限 |
| --- | --- |
| 管理画面 | ログイン、CSRF、全体ロール・サイト権限、変更確認。root権限は持たない |
| 管理用CLI・タイマー | 管理DBを読み、登録済みのagent操作を要求する |
| 特権agent | 入力の再検証、許可された操作・対象・参照の確認、ファイル・プロセス操作 |
| Apache | 専用の `pjas-apache`。アプリ実行ユーザーと分離 |
| 新規通常サイト（v1） | サイト専用UID/GID・サイト別FPM。公開コードはroot所有、共有データだけ書き込み可能 |
| 未移行の通常サイト | 互換性のため従来の共通ユーザーを維持。設定画面から隔離へ移行 |
| 隔離コンポーネント（v2） | 管理者が割り当てた専用ユーザー・プライマリグループ |

RPCの許可一覧は [AgentClient::OPS](../app/Agent/AgentClient.php)、実行先は [agentの登録表](../agent/pjas-agentd.php) にあります。`tests/agent_ops_parity.php` で一致を確認します。任意のrootコマンド本文を渡す汎用RPCはありません。通常デーモンの実行内容やApache設定には、それぞれの検証・管理者確認があります。

Web側の権限確認だけを特権操作の根拠にはしません。agentは対象サイト、入力パス、固定コミット、root管理の許可台帳などを改めて確認します。RPCソケットへ接続できる管理用プロセスとroot管理者は信頼境界の内側です。監査用のactor文字列は外部APIトークンの代わりではありません。

新規サイトは専用ユーザーで分離します。移行前の既存サイト同士は共通ユーザーのリスクが残ります。Apacheと旧PHPのUIDも分け、旧サイトからサイト別FPMソケットへ接続する経路を閉じます。v2は専用UID/GID、root所有のコード、個別FPM、systemdの書き込み先制限を使用します。同じホストのroot侵害を防ぐ境界ではありません。

## コードと永続データ

通常サイトの配置例です。

```text
/var/www/billing/
├── releases/
│   ├── 20260815-101500/
│   └── 20260814-183012/
├── shared/                 # .env、DB、アップロード等
└── current -> releases/20260815-101500
```

登録ファイルはリポジトリのルートに置く **JSON形式の `.pjas`** です。YAML形式の `.pjas.yml` は読み込み対象ではありません。[v1仕様](pjas-manifest.md) と [v2仕様・運用](pjas-cert.md) を参照してください。

v2も `releases/current` を使いますが、リリースIDは通常サイトの日時形式とは異なります。コードはagent所有（本番ではroot）で保護し、CA状態などは管理者が指定した公開ルート外の領域に保存します。通常サイト用の共通デプロイ・ファイル編集・削除経路は拒否します。

## 公開と切り戻し

通常サイトでは、取得・展開・検疫・共有データの引き継ぎ・許可された準備処理を経て、PHPやApacheの検査後に `current` を切り替えます。リロード・HTTPヘルスチェックに失敗した場合は、自動切り戻しの設定に従って直前のコードへ戻します。

初回公開時には既存ファイルをリリースとして取り込む経路があります。公開前の差分確認・日時指定公開は [運用機能](operations.md)、既存サイトの取り込みは [サイト運用](sites.md) を参照してください。

v2では設定のレビュー・適用、固定コミットのコード公開、初期化、起動を分けます。初期化の実行ID・完了状態を保存し、中断後にCAを自動再生成しません。コードの切り戻しで、CA状態や管理DBを巻き戻すこともありません。

コードとデータの復旧は別です。DBスキーマを変更した後に旧コードへ戻す場合、アプリ側の互換性確認が必要です。

## Apache・TLS

通常の設定生成は [Web側のプレビュー](../app/Domain/VhostRenderer.php) と [agent側](../agent/ops/Vhost.php) にあります。既存の独自設定の継承、エラーページ部分更新、設定履歴からの復元は別の操作として扱います。設定検査・リロードに失敗した場合は、対象操作の復旧処理を実行します。

標準のTLSは共通のCloudflare Origin CA証明書です。追加のサイト別TLSは、root管理のプロバイダー設定で共通・手動配置・pjas-certを選びます。pjas-cert連携は利用エンジンに合わせたアダプターが必要です。証明書・鍵・SAN・期限・チェーン・用途を確認し、切替後はSNI付き実接続も検証します。詳しくは [v2のサイト別TLS](pjas-cert.md#サイト別tls) を参照してください。

## 保存先とデータモデル

| 保存先 | 内容 |
| --- | --- |
| 管理用SQLite DB | サイト、リリース、ジョブ、利用者、監査、予約・通知等 |
| `component_sites` テーブル | v2の表示・監視用キャッシュ。許可判断の根拠にはしない |
| `/var/lib/pjas-control` | root管理の接続設定、バックアップ、v2状態・レビュー・監査等 |
| `/var/lib/pjas-repositories` | 取得元、固定コミットのプレビュー、v1初回設定台帳 |
| `/var/lib/pjas-daemons` | 通常デーモンの関連付け台帳・起動スクリプト |
| `/etc/pjas/components.json` | v2の管理者許可台帳。Webから更新するRPCはない |
| `/etc/apache2/sites-available/.pjas-history` | 公開設定のGit履歴。GitHubへは送信しない |

Web用DBの定義は [db/schema.sql](../db/schema.sql)、追加カラムの移行は [Db::migrate](../app/Support/Db.php) を参照してください。個別の保存パスは設定で変更できます。移行・バックアップ時は、設定ファイルとsystemdの書き込み許可も合わせて確認します。

## 実装済み機能と検証の範囲

登録・公開・切り戻し、共有データ、ジョブログ、Apache設定、GitHub App、暗号化バックアップ、予約公開、試験公開、サイト権限、TOTP、監視・通知、v2の隔離コンポーネントを実装しています。具体的な制約は各運用ガイドに記載しています。

テスト用コマンドによる失敗再現と、本番ホストのsystemd・FPM・実UID・外部サービスの確認は区別します。[開発・検証](development.md) に、ローカルで実行する検査と対象ホストでの受け入れ確認をまとめています。
