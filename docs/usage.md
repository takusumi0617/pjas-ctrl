# 日常操作

[目的別ガイド](../README.md) / [更新・保守](maintenance.md) / [障害時の復旧](recovery.md)

## ホームで状態を確認する

ホームは要対応のサイトを先に表示します。「正常」は新しい確認結果がある場合だけ表示します。3分を超えた結果は期限切れ、取得失敗は状態不明、一時停止は公開停止として扱います。HTTPが成功していても、常駐処理・証明書・バックアップなどに問題があれば確認が必要です。

サイト一覧とサイト詳細も同じ判定を使用します。日時は日本時間です。「表示を更新」は保存済み結果と現在の公開状態の再表示です。サイトの「いま動作を確認する」はHTTP検査を実行します。

管理者は「サーバーとctrl」でCPU、メモリ、ディスク、主要サービス、更新候補、設定変更を確認します。「確認済み」はお知らせを読んだ記録であり、異常そのものの解消ではありません。

## サイトを登録する

「サイト一覧 → サイトを登録」で、名前、公開アドレス、公開フォルダ、サイトの種類を設定します。取得元はGitHub、圧縮ファイル、登録のみから選べます。GitHub App認証ならprivateリポジトリも利用できます。

- 公開フォルダは`public`やビルド結果の`dist`にします。設定・DB・秘密情報を含むプロジェクト全体を公開しないでください。
- 新規サイトは専用ユーザー・専用FPMを使用します。静的サイトはPHPを有効にしません。
- `.pjas`を読み込む場合は、固定コミットから取得した構成と初回実行内容を確認して登録します。形式は[リファレンス](reference.md)を参照してください。
- サーバー上に既存の配置がある場合は「サーバーから一括登録」と、サイト概要の「既存ファイルを取り込む」を使用します。既存サイトの隔離・PHP変更は[保守手順](maintenance.md)です。

## コードを公開・切り戻しする

サイト詳細の「新しいバージョンを公開」から取得元を選び、公開前の差分・動作確認設定・共有データを確認します。公開準備と本番切り替えは別の工程です。予約公開は指定した時刻に実行します。実行した利用者の公開権限が失われた予約は開始しません。

「以前のバージョンに戻す」はコードの切り戻しです。DBの内容・構造や利用者のアップロードは戻りません。データを戻す場合は[復旧](recovery.md)を使います。試験公開には専用URLと認証情報を使用し、本番の秘密情報・DBを意図せず共有しないよう確認します。

複数コンポーネントのサイトでは「実行環境」で構成変更・コード公開・切り戻しを行います。CA初期化やCA状態の復元をコード更新の代わりに実行しないでください。

## サイト詳細の使い分け

| 場所 | 操作 |
| --- | --- |
| 概要 | 公開・監視状態、登録情報、最近の作業 |
| 実行環境 | PHP・専用ユーザー、移行状況、処理別の構成・公開・バックアップ |
| 常駐・定期処理 | サイトに関連付けたサービスの起動停止、設定、cron |
| 設定 | 公開アドレス、公開フォルダ、HTTP検査、共有データ、保持数 |
| 作業の履歴 | 結果とログ。切断時は受信済み内容を保持して再接続 |
| 詳細 | コードの履歴、公開設定の差分・履歴、ファイル閲覧 |

設定の保存だけで稼働中のApache設定は変わりません。「登録内容を保存済み・公開設定は未確認」の案内から差分を確認して反映します。専用環境では`.htaccess`と手書きの追加設定を使わず、管理機能が配信設定を生成します。従来の「標準エラーページだけ更新」も残しています。

公開スイッチはサイトのHTTP応答を一時停止ページに切り替えます。外部プロセスや書き込み元まで停止する操作ではありません。DB移行・復元時は、常駐処理・cron・外部の書き込みも止めます。

## 常駐・定期処理

処理はサイトの実行ユーザーで動きます。新規の隔離済みサイトでは専用ユーザーです。起動コマンド、作業フォルダ、環境変数ファイル、実際の実行ユーザーを確認してください。

起動設定を保存しても、実行中のプロセスには再起動まで反映されません。既存サービスの編集は対応している形式だけで利用できます。関連付け解除はctrlの管理台帳から外す操作で、サービス定義・上書き設定・稼働状態を維持します。サービス自体の削除や停止とは区別します。

cronの時刻はサーバーのタイムゾーンに従います。コマンドへパスワードやAPIキーを直書きせず、保護された設定ファイルを参照します。定期処理の有効・無効と、直近実行の成功・失敗は別の状態です。

## GitHub・通知・ログイン保護

「接続設定と初回準備」でGitHub Appを作成・登録し、対象リポジトリを許可します。読み取りにはContents権限を使います。秘密鍵とWebhookの合言葉はroot管理領域へ保存します。サイトの取得元と、ctrl自身の更新元は別に管理します。

通知方法はDiscord、汎用Webhook、メールから選べます。保存後にテスト送信します。DiscordのWebhook URLは秘密情報です。空欄保存は保存済みのURLを維持します。

異常・復旧の状態変化で通知し、同じ異常を毎分送りません。送信エラーは5分以上空け、最大5回・24時間以内に再送します。サーバーそのものの停止は内部から通知できないため、外部監視も必要です。

「利用者とサイトの権限」で管理者・公開担当・閲覧者とサイト範囲を設定します。「ログインの保護」で二段階認証・復旧コード・信頼済み端末を管理します。権限の境界は[セキュリティ](security.md)を参照します。

## 管理解除・削除

サイトの設定から管理解除または復元可能な削除を選び、残すデータ・停止する処理・公開への影響を確認します。「削除済みサイト」で結果と復元を確認します。復元可能期間後の削除は取り戻せないため、必要なバックアップを先に保存します。
